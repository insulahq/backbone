# NetBird Peer Role

> **Status:** COMPLETE — Ready for deployment  
> **Purpose:** Deploy NetBird peer client for mesh connectivity  
> **Deployment:** ns1, ns2, admin1, and workstation (all servers in the mesh)

## Overview

This role installs and configures the NetBird peer client on servers that need to connect to the NetBird mesh network. The peer client enables secure WireGuard-based connectivity between all platform servers.

**Use cases:**
- Connect ns1 and ns2 to the mesh (in addition to running Management services)
- Connect admin1 to the mesh (for Management API to access PowerDNS API on ns1)
- Connect admin workstation to the mesh (for secure SSH access to all servers)

## Architecture

```
NetBird Mesh:
  ├── ns1 (100.76.x.x)        — Management + Peer
  ├── ns2 (100.76.x.x)        — Management + Peer
  ├── admin1 (100.76.x.x)     — Peer only
  └── workstation (100.76.x.x) — Peer only

All peers can communicate via WireGuard tunnel
```

**Note:** ns1 and ns2 run **both** the Management services (via `netbird_management` role) and the peer client (via this role). This allows them to participate in the mesh like any other peer.

## Requirements

- NetBird Management server deployed (via `netbird_management` role)
- Setup key generated during Management server deployment
- Internet access to download NetBird binary

## Role Variables

### Required Variables

Set in `group_vars/all.yml`:

```yaml
netbird_management_url: "https://netbird.phoenix-host.net"
netbird_setup_key: <64-char-setup-key>  # Generated by netbird_management role
```

### Default Variables

See `defaults/main.yml` for all configurable options.

**Key defaults:**
- `netbird_peer_version: "0.28.0"`
- `netbird_install_method: binary`
- `netbird_install_dir: /usr/local/bin`
- `netbird_config_dir: /etc/netbird`
- `netbird_autostart: true`
- `netbird_log_level: info`

## Dependencies

- `netbird_management` role must be deployed first (to generate setup key)

## Example Playbook

```yaml
# Deploy NetBird peer on all mesh participants
- name: Deploy NetBird peer client
  hosts: all  # ns1, ns2, admin1, workstation
  roles:
    - netbird_peer
```

## Deployment

**Deploy to all servers:**
```bash
cd /config/hosting-platform/ansible
ansible-playbook site.yml --tags netbird_peer
```

**Deploy to specific servers:**
```bash
# Just ns1 and ns2
ansible-playbook site.yml --limit ns1,ns2 --tags netbird_peer

# Just admin1
ansible-playbook site.yml --limit admin1 --tags netbird_peer
```

## What This Role Does

1. **Downloads NetBird binary**
   - Fetches from official GitHub releases
   - Extracts to `/usr/local/bin/netbird`
   - Verifies installation with `netbird version`

2. **Creates systemd service**
   - Service file at `/etc/systemd/system/netbird.service`
   - Auto-start on boot
   - Restart on failure

3. **Enrolls peer with Management server**
   - Uses setup key to authenticate
   - Connects to Management server at `netbird_management_url`
   - Creates config at `/etc/netbird/config.json`
   - Only runs once (skipped if already enrolled)

4. **Starts NetBird service**
   - Enables systemd service
   - Waits for connection to be established
   - Verifies peer status

## Post-Deployment

### 1. Verify Peer Status

```bash
# SSH to any server
ssh -i ~/phoenix-host.key root@23.88.111.142

# Check NetBird status
netbird status

# Expected output:
# Daemon status: Running
# Management: Connected
# Signal: Connected
# Peers: X connected
```

### 2. Get NetBird IP

```bash
# Get assigned NetBird IP
netbird status | grep "NetBird IP"

# Example output:
# NetBird IP: 100.76.182.198/16
```

### 3. Test Mesh Connectivity

```bash
# From ns1, ping ns2 via NetBird IP
ping -c3 100.76.92.172

# From admin1, ping ns1 via NetBird IP
ping -c3 100.76.182.198
```

### 4. Verify All Peers Connected

```bash
# List all connected peers
netbird status --detail

# Or via Management API (from ns1)
curl -H "Authorization: Bearer $TOKEN" \
  https://netbird.phoenix-host.net/api/peers
```

## Firewall Requirements

NetBird requires:
- **UDP 51820** (WireGuard) — outbound to Management server
- **TCP 443** (HTTPS) — outbound to Management server

These are configured in the `common` role nftables template.

## Troubleshooting

### Peer not connecting

```bash
# Check NetBird service status
systemctl status netbird

# Check logs
journalctl -u netbird -n 50 --no-pager

# Restart service
systemctl restart netbird
```

### Setup key invalid

```bash
# Generate new setup key on Management server (ns1)
ssh root@23.88.111.142
docker exec netbird-management netbird setup-keys create

# Re-enroll peer
netbird down
netbird up --setup-key <new-key>
```

### Cannot reach other peers

```bash
# Check NetBird routing
ip route show | grep wt0

# Check peer list
netbird status --detail

# Verify firewall allows WireGuard
nft list ruleset | grep 51820
```

## Re-enrollment

If you need to re-enroll a peer:

```bash
# 1. Stop and remove NetBird
systemctl stop netbird
rm -rf /etc/netbird/config.json

# 2. Re-run Ansible (will detect missing config and re-enroll)
ansible-playbook site.yml --limit <hostname> --tags netbird_peer
```

## Upgrading NetBird

```bash
# Update version in group_vars/all.yml
netbird_peer_version: "0.29.0"

# Force reinstall
ansible-playbook site.yml --tags netbird_peer -e netbird_force_reinstall=true
```

## Integration with Other Roles

### PowerDNS API Access

Management API on admin1 uses NetBird mesh to access PowerDNS API on ns1:

```yaml
# admin1 → ns1 PowerDNS API via NetBird
powerdns_api_url: http://100.76.182.198:8081  # ns1 NetBird IP
```

### SSH Break-Glass

SSH stays open on all servers (per user requirement), but NetBird provides the primary access method:

```bash
# Preferred: SSH via NetBird mesh
ssh root@100.76.182.198  # ns1 NetBird IP

# Break-glass: SSH via public IP (if NetBird is down)
ssh -i ~/phoenix-host.key root@23.88.111.142
```
